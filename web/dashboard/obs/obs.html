How it works

Writes an InstantClone entry next to Twitch and YouTube in OBS's Settings → Stream → Service list. Multi-track via InstantClone works out of the box on Auto. OBS reads that list when it starts and writes it back when it quits, so InstantClone only changes it while that OBS is closed. If you change InstantClone's ports while OBS is closed, the entry follows at once.

Each OBS on this PC has its own list: the installed one and every portable one. A portable OBS shows up here once it has been open while InstantClone runs, or pick its obs64.exe with Using a portable OBS?

How it works

Streamlabs stays signed in with Twitch, so its title, category, chat and alerts keep working, and Enhanced Broadcasting and the VOD track work too. InstantClone points Streamlabs' Twitch Enhanced Broadcasting setup at itself (a file in %APPDATA%\slobs-client) and leaves it there until you press Disconnect, which puts Streamlabs back as it was. Open InstantClone before you go live: while it's closed, Streamlabs can't start an Enhanced Broadcasting stream.

Go live with Enhanced Broadcasting off and InstantClone switches it on for that stream and asks Twitch for one video track: the same stream you picked, through InstantClone.

A Streamlabs signed in with YouTube or Kick can't come through yet: sign it in with Twitch. Streamlabs' own Multistream sends around InstantClone: add your other platforms in Destinations instead.

This is new. If something breaks or confuses you, report it.

The rules that actually matter for Kick. details
Kick requirements (and the B-frames myth)

Kick's stream servers run on AWS IVS (low-latency). The rules it actually enforces: H.264, CBR rate control, keyframe interval 2 s, bitrate ≤ 8000 kbps, up to 60 fps.

B-frames: despite what a lot of older guides say, Kick's normal RTMP server (IVS low-latency, Main profile) accepts B-frames. The strict "no B-frames" rule is AWS IVS real-time / WHIP, a different server Kick doesn't use for standard OBS streaming. So you usually don't need to touch B-frames at all.

If Kick does reject your stream, set B-frames to 0 in OBS → Settings → Output (Advanced): x264 B-frames → 0, NVENC Max B-frames → 0. That's safe for Twitch and YouTube too. Note InstantClone passes on one encode without re-encoding, so B-frames can't be stripped for Kick alone. It's an OBS-side toggle that applies to every destination.

Using Twitch Enhanced Broadcasting? Twitch picks the encode settings for you (including B-frames), so your manual OBS B-frames box may not apply while EB is on.

Delay and cuts work the same either way: InstantClone cuts on keyframes (IDRs), which B-frames don't affect.

Legacy: launch OBS with Enhanced Broadcasting
Start OBS pre-wired for Twitch Enhanced Broadcasting (the multi-resolution video ladder), with no destination editing needed. Session-only: reopen OBS normally and it streams plain again. Close OBS first: a second OBS next to an open one never gets the flag.
Heads-up: Enhanced Broadcasting needs an enabled Twitch destination with a stream key. OBS will still launch, but EB won't engage until you add one in the Destinations tab.
For VOD audio on your OBS version, use the VOD unlocker script in System → Twitch & OBS, and the registered InstantClone service for Enhanced Broadcasting. These launchers are only for OBS older than 32.2.
EB + VOD: the legacy VOD path, for OBS before 32.2. It turns on VOD audio mode on your Twitch destination and writes OBS's VOD-track unlock flag. Close OBS before pressing it or the flag write is blocked.
